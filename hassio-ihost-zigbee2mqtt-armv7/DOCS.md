# Zigbee2MQTT armv7 2.12.1 для Sonoff iHost

Дополнение предназначено для Home Assistant Supervisor на архитектуре `armv7`, прежде всего для Sonoff iHost.

## Важное предупреждение

Это отдельное дополнение со slug:

```text
zigbee2mqtt_armv7
```

Оно не заменяет автоматически старое дополнение `zigbee2mqtt_patched_mqtt`.

Нельзя одновременно запускать старую и новую версии. Они используют один и тот же:

- встроенный радиомодуль `/dev/ttyS4`;
- MQTT base topic;
- каталог `/config/zigbee2mqtt`.

Первая версия помечена как `experimental`, а автозапуск отключён. После успешной проверки автозапуск можно включить вручную на странице дополнения.

## Настройки встроенного радиомодуля iHost

```yaml
serial:
  port: /dev/ttyS4
  adapter: ember
  baudrate: 115200
  rtscts: false
```

## MQTT

Дополнение использует MQTT-сервис, опубликованный Supervisor. Mosquitto armv7 из этого репозитория объявляет `mqtt:provide`, а Zigbee2MQTT — `mqtt:need`.

При необходимости можно явно указать брокер:

```yaml
mqtt:
  server: mqtt://2c914bdd-mosquitto:1883
  user: mqtt_user
  password: ваш_пароль
```

Явно заданные параметры имеют приоритет над автоматическим обнаружением MQTT-сервиса.

## Безопасный переход со старой версии 2.6.3

1. Создайте полный backup Home Assistant.
2. Отдельно скопируйте каталог `/config/zigbee2mqtt`.
3. Запишите текущие параметры MQTT и serial.
4. Установите новое дополнение, но не запускайте его.
5. Остановите старое `Zigbee2MQTT patched MQTT 2.6.3-1`.
6. Отключите автозапуск старого дополнения.
7. Запустите `Zigbee2MQTT armv7` и откройте журнал.
8. Проверьте устройства, группы, binding, карту сети, MQTT discovery и автоматизации.
9. Не удаляйте старое дополнение несколько дней — оно остаётся резервным вариантом для отката.

Для отката сначала остановите новую версию и только затем запускайте старую.
